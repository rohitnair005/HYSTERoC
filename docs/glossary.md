# Glossary — HYSTERoC

This document defines technical terms, acronyms, and abbreviations used in the HYSTERoC repository. The definitions follow Simplified Technical English clarity principles.

---

## 1. Hardware and network terms

### Arbiters and Allocation
* **Arbiter**: A hardware circuit that selects one request among competing requests. HYSTERoC uses round-robin arbiters to prevent starvation.
* **Crossbar**: A hardware switch matrix that connects any input port to any non-conflicting output port.
* **Switch Allocator**: Logic that reserves output ports and connects crossbar paths for admitted packets.

### Network-on-Chip (NoC) Concepts
* **Flit (Flow Control Unit)**: The basic unit of data transfer on a link. In HYSTERoC, a flit contains 18 bits: 2 bits for flit type and 16 bits for data payload.
* **Header Flit**: The first flit of a packet. It contains destination coordinates, source coordinates, and packet identification.
* **Body Flit**: A payload flit that carries data between the header flit and tail flit.
* **Tail Flit**: The final flit of a packet. It releases port reservations and carries the checksum word.
* **Wormhole Switching**: A switching technique where a packet streams through routers flit-by-flit without waiting for the full packet to arrive before forwarding.
* **Mesh Topology**: A 2D grid network where routers connect to adjacent cardinal neighbours (North, South, East, West) and a local processing node.

### Routing Terms
* **Deterministic Routing (XY)**: A fixed routing algorithm that routes along the X dimension completely before turning into the Y dimension.
* **Adaptive Routing**: A dynamic routing algorithm that chooses output ports based on current local network congestion.
* **Odd–Even Routing**: A deadlock-free turn model that restricts vertical turns based on column coordinate parity.
* **Turn Model**: A methodology for designing deadlock-free wormhole routing algorithms by preventing cyclic dependencies in the channel dependency graph.

## 2. Control and algorithm terms

### Hysteresis and Filtering
* **Dead Band**: The region between the lower threshold (`TLOW`) and upper threshold (`THIGH`). Congestion fluctuations within this band trigger zero mode switches.
* **EWMA (Exponentially Weighted Moving Average)**: A digital low-pass filter that calculates running averages:
  $$S_{\text{next}} = S - (S \gg 3) + C$$
* **Hysteresis**: A control characteristic where the system state depends on past history. Upper and lower thresholds prevent rapid switching when inputs fluctuate near a single boundary.
* **Ping-Pong Effect**: Rapid, undesirable oscillations between routing modes caused by signal noise near a switching threshold.
* **Dwell Time**: The elapsed time (in clock cycles) that the network remains in a single routing mode before switching.

### State and Mode Switching
* **Active Mode (`active_mode`)**: The current routing mode used across all mesh routers (0 = Deterministic, 1 = Adaptive).
* **Requested Mode (`req_mode`)**: The target mode generated by the hysteresis controller.
* **Drain-and-Switch (`SWITCH_POLICY = 0`)**: A mode-switching policy that blocks packet injection and drains all in-flight flits before changing modes.
* **No-Drain Switch (`SWITCH_POLICY = 1`)**: A direct mode-switching policy that updates routing modes while packets remain in transit, using shared Odd–Even rules.
* **Quiescence**: The state where all router FIFOs are empty, all links are idle, and all source generators are stopped.

## 3. Verification and tools

* **DUT (Device Under Test)**: The hardware module being evaluated (in this repository, `noc_top`).
* **SVA (SystemVerilog Assertions)**: Formal verification statements embedded in code to verify protocol invariants during simulation.
* **Scoreboard**: A verification component that stores transmitted transactions and compares them against received transactions to check data integrity and order.
* **UVM (Universal Verification Methodology)**: An industry-standard SystemVerilog class library used for structured testbench creation.
* **Watchdog**: A safety timer that detects simulation or hardware lockup and initiates safe error transitions.
